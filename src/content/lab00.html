첫 번째 셀

아래 상자가 이 사이트의 '셀'입니다. 위쪽 회색 부분이 입력할 코드이고, 아래 '출력'이 그 코드를 실제로 실행한 결과입니다. 오른쪽 위 복사 버튼을 누르면 코드가 복사되므로, Colab(나 절)이나 JupyterLab(다 절)의 빈 코드 셀에 Ctrl+V로 붙여 넣고 실행하면 같은 출력이 나옵니다. 셀 번호는 이 페이지 안의 순서입니다. 한 페이지의 셀은 위에서부터 차례로 실행해야 합니다(라 절).

  1. # 첫 번째 셀: …# 뒤의 글은 주석(comment)입니다. 파이썬은 이 부분을 실행하지 않습니다. 코드가 무엇을 하는지 적어 두는 메모입니다.
  2. print("안녕하세요, 파이썬!")print()는 괄호 안의 값을 출력 영역에 찍습니다. 큰따옴표로 감싼 글자를 문자열(string)이라고 합니다.
  3. bwt_g = 2523=는 수학의 '같다'가 아니라 오른쪽 값을 왼쪽 이름에 저장하라는 뜻입니다(대입). 이제 커널이 "bwt_g는 2523"을 기억합니다. 저장만 하므로 출력은 없습니다.
  4. bwt_kg = bwt_g / 1000저장해 둔 bwt_g를 꺼내 1000으로 나누고(/), 결과 2.523을 새 이름 bwt_kg에 저장합니다.
  5. bwt_kg셀의 마지막 줄이 값이면 print() 없이도 그 값이 출력에 표시됩니다(노트북의 기능). 같은 줄이 셀 중간에 있으면 아무것도 표시되지 않습니다.

출력 읽기

  1. 1print()가 찍은 글자입니다.
  2. 2마지막 줄 bwt_kg의 값입니다. 2523 g = 2.523 kg. JupyterLab에서는 이 값 왼쪽에 [1]: 같은 번호가 함께 보이기도 합니다.

2523을 3100으로 바꿔 다시 실행하면 마지막 출력이 3.1로 바뀝니다. 마지막 줄 bwt_kg를 지우고 실행하면 print 결과만 보이고 3.1은 표시되지 않습니다. 값은 여전히 커널이 기억하고 있으므로, 새 셀에 bwt_kg만 쓰고 실행하면 다시 볼 수 있습니다.

pandas의 DataFrame은 엑셀 시트와 비슷한 표입니다. 한 행(row)은 관측 단위 하나(여기서는 산모 한 명), 한 열(column)은 변수 하나입니다. 왼쪽의 행 이름표를 인덱스(index)라고 하고, 열 하나를 따로 꺼낸 한 줄짜리 자료를 Series라고 합니다. 열마다 값의 종류인 자료형(dtype)이 정해져 있습니다.

  4. 4마지막 줄 = 오류의 종류와 설명. TypeError(자료형 오류): 'str'(문자열)과 'int'(정수)는 /로 나눌 수 없다. 원인은 "2523"의 따옴표이고, to_kg(2523)으로 고치면 됩니다. CSV에서 읽은 숫자 열이 글자로 저장되어 있을 때(바 절의 info 출력 해설 3)도 같은 오류가 납니다.

자주 만나는 오류

KeyError: 없는 열 이름

KeyError: 'bwtt'는 "'bwtt'라는 열(키)이 없다"는 뜻입니다. 대괄호 안의 열 이름에 오타가 있거나, 대소문자("BWT")나 빈칸("mean radius"와 "meanradius")이 다를 때 납니다. Colab에서는 이 오류의 traceback이 pandas 내부 경로를 포함해 꽤 길게 나오지만, 마지막 줄만 보면 됩니다.

  1. "bwtt" in df.columnsin은 '안에 있는가'를 묻는 연산자로, True 또는 False를 돌려줍니다. 열 이름이 헷갈리면 print(df.columns.tolist())로 목록을 출력해 정확한 이름을 복사해 쓰는 것이 가장 확실합니다.

ModuleNotFoundError: 설치하지 않은 패키지

No module named 'pingouin'은 그 이름의 패키지가 설치되어 있지 않다는 뜻입니다(pingouin은 통계 패키지의 하나로, 여기서는 설치하지 않은 예로 썼습니다). 노트북 셀에서 %pip install pingouin(Colab에서는 !pip install pingouin도 가능)으로 설치한 뒤 다시 import합니다. Colab에서 어제는 되던 import lifelines가 오늘 이 오류를 낸다면 런타임이 새로 바뀐 것이므로 설치 셀부터 다시 실행합니다. 설치 이름과 import 이름이 다른 패키지도 있습니다. scikit-learn은 pip install scikit-learn으로 설치하고 import sklearn으로 불러옵니다.

FileNotFoundError: 없는 파일

[Errno 2] No such file or directory는 그 위치에 그 이름의 파일이 없다는 뜻입니다. 확인할 것은 네 가지입니다. 파일 이름의 오타, 확장자(Windows 탐색기가 확장자를 숨겨서 data.csv가 실제로는 data.csv.xlsx인 경우), 파일을 올리지 않았거나 런타임이 바뀌어 사라진 경우(나 절), 현재 작업 폴더가 생각한 곳이 아닌 경우입니다. 현재 폴더는 셀에서 import os 다음 줄에 os.getcwd()를 실행하면 확인할 수 있고, 헷갈리면 전체 경로를 씁니다(마 절).

경고(warning): 실행은 되었지만 확인이 필요함

오류(error)가 나면 셀이 그 줄에서 멈추지만, 경고(warning)는 실행을 끝까지 마친 뒤 "결과를 확인하라"고 알려 주는 메시지입니다.

  1. np.log(df["ptl"])이전 조산 횟수에 자연로그를 취합니다. ptl은 대부분 0인데, log(0)은 정의되지 않습니다(−∞로 발산).

출력 1의 -inf는 음의 무한대입니다. 셀은 오류 없이 끝났지만, 이 열로 평균을 내거나 회귀모형에 넣으면 결과가 망가집니다. 아래쪽의 RuntimeWarning: divide by zero encountered in log가 그 신호입니다. 0이 있는 변수는 로그 변환 전에 변수 정의를 다시 생각하거나, 목적에 맞으면 np.log1p()(log(x + 1))를 씁니다. 이 밖에 FutureWarning, DeprecationWarning은 "앞으로 버전에서 이 기능이 바뀐다"는 안내로, 당장 결과에는 영향이 없습니다. 패키지 버전에 따라 이 사이트에는 없는 경고가 Colab에서 보일 수 있습니다.

AI나 선배에게 질문

셀 코드 전체, 오류 메시지 전체(traceback), 패키지 버전(라 절 셀 4)을 함께 붙이면 원인을 훨씬 빨리 찾습니다. "안 돼요"보다 "무엇을 하려 했고, 무엇이 나왔는가"를 씁니다. 환자 자료나 개인정보는 붙이지 않고, 필요하면 df.head() 대신 열 이름과 자료형(df.info())만 보여 줍니다.

정리

  • traceback은 맨 아래 줄(오류 종류와 설명)부터 읽고, 그다음 내 셀의 줄 번호를 찾습니다. 패키지 내부 경로는 대개 건너뛰어도 됩니다.
  • KeyError는 열 이름, ModuleNotFoundError는 설치, FileNotFoundError는 경로, NameError는 셀 실행 순서, UnicodeDecodeError는 인코딩 문제입니다.
  • 경고는 실행을 멈추지 않지만 결과가 망가졌을 수 있다는 신호입니다(예: log(0) → −∞).
  • 질문할 때는 코드, 전체 오류 메시지, 패키지 버전을 함께 보여 주고, 환자 자료는 붙이지 않습니다.
