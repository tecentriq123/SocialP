a.청구 표를 잇고 한 줄의 단위 확인하기

세 표는 각각 무엇이 한 줄인가?

표마다 행 수와 사람 수를 함께 세면 한 줄이 무엇인지 보입니다. 날짜 열은 read.csv()가 글자로 읽으므로 as.Date()로 바꿉니다. 자료는 보건통계학 기초 14장 a 절의 예제 코호트를 청구자료 모양으로 되돌린 가상의 표 세 개입니다. 자격 표(person)는 한 사람이 한 줄, 명세서 표(visit)는 진료 한 건이 한 줄, 처방 표(rx)는 처방 한 건이 한 줄입니다.

  1. 1rx_date: chr. 날짜가 글자입니다. 이대로는 빼거나 비교할 수 없어 바로 아래 줄에서 날짜로 바꿉니다.
  2. 2행 10,306, 54,370, 111,882. 자격 표만 행 수와 사람 수가 같습니다.
  3. 3사람 10,306명. 세 표 모두 같은 사람들입니다. 명세서와 처방은 한 사람이 여러 줄이라, 이 표로 바로 사람을 세면 안 됩니다.

표를 이을 때 왜 행이 사라지나?

merge()는 두 표 모두에 있는 행만 남기는 것이 기본값이고(all = FALSE), 짝이 없는 행은 경고 없이 뺍니다. 기준이 되는 표의 사람을 모두 남기려면 all.x = TRUE를 적고, 이은 뒤 행 수와 사람 수를 셉니다.

  1. 1기본값 1,277행·1,148명 대 all.x = TRUE 10,435행·10,306명. 자격 표에 입원 명세서를 기본값으로 이으면 입원이 없는 9,158명이 사라집니다. 코호트 표에 다른 표를 붙일 때 이런 일이 생기면 분석 대상이 조용히 바뀝니다.

한 사람의 여러 행을 한 줄로 모으는 일은 aggregate()로 합니다. 마지막 줄은 사람마다 첫 입원일을 구한 것입니다.

보건통계학 기초 14장의 '직접 분석' 상자에 있던 내용입니다.

파이썬에서는 파일마다 pandas로 불러와 환자 ID나 명세서 번호로 merge()해 잇습니다. merge()의 기본값은 how="inner"여서 양쪽 파일에 모두 있는 행만 남기고, 짝이 없는 행은 경고 없이 뺍니다. 예를 들어 명세서 일반내역에 원외처방 내역을 이으면 원외처방이 없는 명세서가 모두 사라집니다. 짝이 없는 행도 남겨야 하면 how="left"를 지정하고, 잇기 전후의 행 수와 환자 수를 세어 확인합니다.

날짜 글자는 pd.to_datetime()으로 날짜로 바꾸고, 한 환자의 여러 행은 groupby().agg()로 한 행에 모읍니다.

첫 처방일과 기존 사용자는 어떻게 가려내나?

제외 기준의 표시는 어떻게 만드나?

제외 기준마다 참·거짓 열을 하나씩 만듭니다. 상병코드는 앞부분이 같으면 같은 병으로 보도록 정규표현식 ^(N185|Z49|Z992)를 주상병과 부상병 열에 모두 적용합니다. 기준을 확인하는 기간은 첫 처방일까지 365일이고(before 0–365), 제2형 당뇨병 진단(E11)은 첫 처방일까지의 모든 명세서로 봅니다.

  1. 118세 미만 14명, 말기신부전 194명, 심부전 입원력 234명, 당뇨병 진단 없음 156명. 아직 겹치는 사람을 빼지 않은 숫자입니다. 흐름표에는 앞 단계에서 이미 빠진 사람을 빼고 적습니다.

c.공백, 중단일, PDC와 양성예측도

처방 기록에서 공백과 중단일은 어떻게 구하나?

처방일에 공급일수를 더해 약이 떨어지는 날을 만들고, 다음 처방일과의 차이로 공백을 구합니다. 공백이 유예기간보다 긴 첫 처방에서 '약이 떨어지는 날 + 유예기간'이 중단일입니다. 예는 보건통계학 기초 14장 c 절의 가상 환자 한 명입니다. 같은 환자의 다음 처방일은 ave()로 환자마다 한 칸씩 당겨 구하므로, 환자가 여러 명이어도 같은 코드가 환자마다 따로 적용됩니다.

  1. 1네 번째 처방 뒤 45일 공백. 유예기간 30일보다 길어 여기서 중단이 정해집니다. 마지막 처방은 다음 처방이 없어 NA입니다.
  2. 2유예기간 30·60·90일의 중단일 2021-10-03, 2022-06-15, 2022-07-15. 유예기간을 60일로 늘리면 45일 공백을 넘어가 마지막 처방까지 이어집니다.
  3. 3첫 365일의 PDC 315/365 = 0.863. 구간 끝을 넘는 공급일수는 잘라 냈습니다. 처방이 겹치지 않을 때만 맞는 간단한 계산이고, 겹치면 14장의 접힌 상자 '처방이 겹치거나, 입원했거나, 약을 바꾸면?'의 규칙을 먼저 정합니다.

위 환자의 계산을 pandas로 옮긴 코드입니다. 실습 환경(실습 0)의 주피터 노트북 셀에 그대로 붙여 넣어 실행합니다. 환자가 여러 명이어도 groupby("pt") 덕분에 같은 코드가 환자마다 따로 적용됩니다.

직접 실행처방 기록에서 공백, 중단일, PDC 구하기
import pandas as pd

# 가상의 환자 한 명의 원외처방 기록 (한 행 = 처방 한 건, supply = 공급일수)
rx = pd.DataFrame({
    "pt": ["P1"] * 6,
    "date": ["2021-03-02", "2021-04-01", "2021-05-06",
             "2021-06-05", "2021-10-18", "2022-01-16"],
    "supply": [30, 30, 30, 90, 90, 90],
})
rx["date"] = pd.to_datetime(rx["date"])       # 글자 → 날짜
rx = rx.sort_values(["pt", "date"])           # 환자별, 날짜순으로 정렬

# 약이 떨어지는 날 = 처방일 + 공급일수
rx["runout"] = rx["date"] + pd.to_timedelta(rx["supply"], unit="D")
# 같은 환자의 다음 처방일 (마지막 처방은 빈칸 NaT)
rx["next"] = rx.groupby("pt")["date"].shift(-1)
# 공백 일수 = 다음 처방일 - 약이 떨어지는 날
rx["gap"] = (rx["next"] - rx["runout"]).dt.days
print(rx[["date", "supply", "runout", "gap"]])

def stop_date(g, grace):
    # 공백이 유예기간보다 길거나 다음 처방이 없는 첫 처방을 찾아
    # 그 처방의 '약이 떨어지는 날 + 유예기간'을 중단일로 돌려줌
    over = g["gap"].isna() | (g["gap"] > grace)
    return g.loc[over, "runout"].iloc[0] + pd.Timedelta(days=grace)

for grace in [30, 60, 90]:
    stop = rx.groupby("pt").apply(stop_date, grace=grace)   # 환자마다 중단일 하나
    print("유예", grace, "일 → 중단일", stop.iloc[0].date())

# 첫 365일의 PDC = 구간 안에서 약이 있던 날 수 ÷ 365
index_date = rx["date"].min()
win_end = index_date + pd.Timedelta(days=365)
days = (rx["runout"].clip(upper=win_end) - rx["date"]).dt.days
covered = days.clip(lower=0).sum()
print("PDC =", covered, "/ 365 =", round(covered / 365, 3))

양성예측도의 신뢰구간은 어떤 방법으로 구하나?

양성예측도는 비율 하나이므로 prop.test(x, n, correct = FALSE)$conf.int로 Wilson 구간을, binom.test()로 정확 구간을 구합니다. 14장 a 절 정의 B의 양성예측도 96.7%(1,391 ÷ 1,438)와 c 절 심부전 입원 정의의 171 ÷ 200입니다.

  1. 1Wilson 95.7–97.5%. 14장 본문의 구간입니다. correct = FALSE를 빼면 연속성 보정이 들어가 조금 넓어집니다.
  2. 2Wald 95.8–97.7%. 비율이 1에 가까워 상한이 위로 치우칩니다. 같은 자료라도 방법에 따라 구간이 달라지므로 방법의 이름을 Methods에 적습니다. 171/200은 Wilson으로 80.0–89.7%입니다.

d.추적 기간과 분석

추적이 끝나는 날은 어떻게 고르나?

사건일, 사망일, 중단일, 자료 종료일 같은 후보 가운데 가장 이른 날을 pmin(…, na.rm = TRUE)로 고릅니다. 사망하지 않은 사람은 사망일이 NA인데, na.rm의 기본값은 FALSE라서 후보 하나만 NA여도 종료일 전체가 NA가 됩니다.

  1. 1기본값: 세 사람 모두 NA. 자료 종료일만 있는 셋째 사람까지 종료일을 잃습니다.
  2. 2na.rm = TRUE: 사건일, 사망일, 자료 종료일. 있는 날짜 가운데 가장 이른 날입니다. 대신 자료 종료일처럼 모든 사람에게 있어야 하는 후보가 비어 있으면 종료일이 엉뚱하게 정해지므로, 그 열에 NA가 없는지 먼저 확인합니다.

발생률과 위험비는 어떻게 구하나?

분석 파일을 만든 뒤 time이 모두 0보다 큰지 stopifnot()으로 확인하고, 군마다 사건 수와 인년을 더해 발생률을, poisson.test()로 정확 신뢰구간을 구합니다. 위험비는 coxph()로 구합니다. 자료는 14장의 분석용 전체 코호트(유예기간 60일의 as-treated 추적)입니다.

  1. 1time 1–2,556일. 0일 이하가 없습니다. R의 coxph()와 survfit()도 파이썬 lifelines처럼 time이 0이나 음수여도 경고 없이 적합하므로, 분석 전에 직접 멈추게 해 둡니다.
  2. 2SGLT2 억제제군 30,826명, 사건 320건, 57,781인년, 1,000인년당 5.54. DPP-4 억제제군은 12.95입니다.
  3. 3정확 구간 4.95–6.18. 14장 본문의 구간입니다.
  4. 4발생률비 0.43(0.38–0.48). poisson.test()는 정확 구간이라 14장의 점수 구간(0.381–0.479)과 하한의 끝자리가 다릅니다.
  1. 1보정 전 0.42(0.38–0.47). 발생률비와 거의 같습니다.
  2. 2보정 후 0.61(0.54–0.68). 14장 표 14-5의 as-treated 분석입니다. 바로 아래 줄처럼 동점 처리를 Breslow로 바꿔도 0.6092로 같았습니다. 공식에 넣을 변수를 직접 적으므로, 환자 번호 같은 열이 공변량으로 잘못 들어갈 일은 없습니다.

중앙 추적기간은 어떻게 구하나?

사건과 중도절단의 역할을 바꿔(1 - event) Kaplan-Meier 곡선을 그리고 그 중앙값을 읽습니다. 역 Kaplan-Meier 방법입니다. 14장 d 절 '논문에서 읽기'의 접힌 상자 '중앙 추적기간은 어떻게 구하나?'의 숫자입니다.

  1. 11.80년. 사건이 없었다면 관찰할 수 있었던 기간의 중앙값입니다.
  2. 2time의 단순 중앙값 1.75년. 사건으로 일찍 끝난 사람의 짧은 time까지 섞여 조금 짧습니다.

약을 끊은 이유가 예후와 관련될 때 쓰는 역확률 중도절단 가중(14장 d 절)은 추적을 구간으로 나눈 자료에서 구간마다 중도절단 확률의 역수를 가중치로 만들고, coxph(Surv(tstart, tstop, event) ~ sglt2, weights = w, cluster = pid)처럼 가중치와 환자 단위의 군집을 함께 넣어 강건 표준오차로 적합합니다. 구간 자료를 만드는 법은 9장 d 절의 survSplit()과 같습니다.

보건통계학 기초 14장의 '직접 분석' 상자에 있던 내용입니다.

0일 이하의 time은 날짜를 빼는 순서가 바뀌었거나, 종료일 후보에 첫 처방일 이전의 날짜(예를 들어 잘못 이어진 이전 입원)가 섞였을 때 생깁니다. lifelines의 CoxPHFitter와 KaplanMeierFitter는 time이 0이나 음수여도 경고 없이 적합합니다. 그래서 분석 파일을 만든 뒤 다음처럼 확인합니다. event_date는 결과 사건일 열입니다.

# 0일 이하의 time이 있으면 여기서 멈춤
assert (d["time"] > 0).all()
# 첫 처방일 당일의 사건 수
print((d["event_date"] == d["index_date"]).sum())

이 장의 전체 코호트 파일(sglt2_cohort_full.csv)에서 time의 최솟값은 1일입니다.

파이썬에서는 lifelines의 KaplanMeierFitter에 사건 여부를 뒤집어 넣습니다.

# 1 - event: 중도절단을 '사건'으로 바꿔 넣음
km = KaplanMeierFitter().fit(d["time"] / 365.25,
                             1 - d["event"])
print(km.median_survival_time_)   # 1.80 (as-treated)

파이썬에서는 구간마다 한 줄인 자료를 만들고 가중치를 직접 계산합니다. 가중치를 넣은 적합에는 lifelines CoxPHFitter에 entry_col, weights_col, 환자 단위로 묶는 cluster_col을 함께 주어 강건 표준오차를 구합니다. CoxTimeVaryingFitter는 가중치를 받기는 하지만 강건 표준오차를 지원하지 않습니다(lifelines 0.30에서 robust=True는 NotImplementedError). 이 과정을 한 번에 해 주는 함수는 lifelines에 없습니다(구간 자료를 만드는 법은 보건통계학 기초 16장 c 절, 프로그램 동작은 보건통계학 기초 16장 d 절의 접힌 상자 '가중치를 쓰는 분석은 표준오차를 어떻게 구하나?').

보건통계학 기초 14장의 장 마무리의 '직접 분석' 상자에 있던 내용입니다.

pandas 3.0, statsmodels 0.15, lifelines 0.30에서 확인한 것입니다. 버전에 따라 다를 수 있습니다.

  • 표 잇기. pandas merge()의 기본값은 how="inner"라서 두 표 모두에 있는 환자만 남기고, 짝이 없는 환자는 경고 없이 뺍니다. 예를 들어 코호트 표에 입원 표를 이으면 입원이 없는 환자가 사라집니다. 코호트에 다른 표를 붙일 때는 how="left"로 잇고, 이은 뒤 행 수가 그대로인지 셉니다.
  • 가장 이른 날 고르기. min(axis=1)은 빈 날짜(NaT)를 건너뛰고 나머지 가운데 가장 이른 날을 고릅니다. 사망하지 않은 사람의 빈 사망일이 무시되는 것은 바라는 동작입니다. 다만 자료 종료일처럼 모든 사람에게 있어야 할 후보가 비어 있으면 종료일이 엉뚱하게 정해지므로, 그 열에 빈칸이 없는지 먼저 확인합니다.
  • Cox 모형의 변수. lifelines CoxPHFitter().fit(df, ...)는 df에 남은 열을 모두 공변량으로 넣습니다. 환자 번호(pid)를 남겨 두면 pid도 변수로 들어갑니다. 실습 14 표본에서는 위험비가 0.6066에서 0.6067로 거의 바뀌지 않았지만, 추적 중에 만든 변수 같은 열이 남으면 결과가 크게 달라질 수 있으므로 넣을 열만 골라 넘깁니다.
  • 0일 이하의 time. lifelines의 Cox 모형과 Kaplan-Meier는 time이 0이나 음수여도 경고 없이 적합합니다. 실습 14 표본에서 30명의 time을 −5일로 바꿔도 위험비가 0.6066에서 0.6070으로 바뀔 뿐 오류가 나지 않았습니다(보건통계학 기초 14장 d 절 '추적은 언제 시작하고 언제 끝나나?'의 접힌 상자).
  • 비율의 신뢰구간. statsmodels proportion_confint()의 기본 method는 정규근사(normal)입니다. 정의 B의 양성예측도 1,391/1,438은 95.8–97.7%, 결과 정의의 171/200은 80.6–90.4%가 나옵니다. 본문의 Wilson 구간(95.7–97.5%, 80.0–89.7%)은 method="wilson"을 적어야 나옵니다.
  • 발생률의 신뢰구간. statsmodels confint_poisson()은 method에 기본값이 없어 적지 않으면 오류가 납니다. method="exact-c"로 정확 구간을 구하면 SGLT2 억제제군은 1,000인년당 5.54(4.95–6.18)입니다. 발생률비의 구간과 검정은 기본값이 score 방법입니다(보건통계학 기초 12장 a 절 '발생률을 비교할 때 무엇을 정하나?').
  • 같은 날의 사건. 같은 날 사건이 여럿일 때 lifelines는 Efron 방법, statsmodels PHReg는 Breslow 방법이 기본값입니다(보건통계학 기초 11장 '내 연구에서 분석하기'의 접힌 상자 '같은 날 사건이 여러 건이면 프로그램은 어떻게 하나?'). 이 코호트에서는 둘 다 보정 위험비가 0.6092였습니다.

e.자발적 보고 자료의 불균형 분석

2×2 표 하나로 지표를 구하려면?

네 칸(그 약·그 사건, 그 약·다른 사건, 다른 약·그 사건, 다른 약·다른 사건)만 있으면 ROR과 IC는 기본 R의 몇 줄로 계산됩니다. 보건통계학 기초 14장 e 절의 가상 보고 자료(보고 100만 건, 당뇨병약 보고 5만 건)입니다. IC의 하한은 감마분포의 2.5% 분위수로 구합니다.

  1. 1당뇨병약 보고를 배경으로 한 SGLT2 억제제–DKA: 관찰 60건, 기대 24건, ROR 3.02(2.25–4.06), IC 1.30(하한 0.92). 14장 본문의 숫자입니다. 바로 위 줄처럼 보고 전체를 배경으로 하면 ROR이 35.53으로 커집니다.
  2. 2시판 첫해 말: 4건, ROR 3.34(1.15–9.71), IC 하한 −0.45. ROR의 하한은 1을 넘지만 IC의 하한은 0 아래라, 지표에 따라 신호 여부가 갈립니다.
  3. 3χ² 3.62(Yates 보정) 대 5.50(보정 없음). chisq.test()는 2×2 표에서 Yates 보정이 기본입니다. Evans 기준(χ² ≥ 4)에 들어가는지가 보정 여부로 갈리므로 어느 쪽을 썼는지 Methods에 적습니다. 칸의 기대 빈도가 작다는 경고도 함께 나옵니다.

보고 단위 자료로 모든 조합을 한 번에 계산하려면?

한 줄이 '보고 하나의 약 하나와 사건 하나'인 표를 pvda 패키지의 da()에 넣으면 모든 약–사건 조합의 관찰 수, 기대 수, IC, ROR, PRR이 한 번에 나옵니다. 여기서는 당뇨병약 보고 5만 건을 그런 표로 만들어 넣었습니다. 배경을 좁히려면 당뇨병약이 있는 보고만 먼저 고른 뒤 넣습니다.

  1. 1SGLT2: obs 60, exp_rrr 24, ic 1.30(ic2.5 0.92), ror 3.02(2.25–4.06). 2×2 표로 구한 값과 같습니다.

da()의 기본값 가운데 결과를 바꾸는 것이 둘 있습니다. rule_of_N = 3이라 보고가 3건 미만인 조합의 ROR과 PRR은 NA로 비우고(IC는 계산함), number_of_digits = 2라 결과를 소수 둘째 자리로 반올림해 돌려줍니다. 5건 기준을 쓰려면 rule_of_N = 5로 바꾸고, 기준값 근처의 조합은 반올림 전 값으로 판정합니다. 모든 조합의 보고 수로 사전분포를 추정해야 하는 EBGM은 openEBGM 패키지가 계산합니다.

파이썬에는 pvda 같은 불균형 분석 패키지가 흔하지 않아, 2×2 표의 지표는 직접 계산합니다.

>>> import numpy as np
>>> from scipy import stats
>>> def disp(a, b, c, d):
...     ror = a * d / (b * c)
...     se = np.sqrt(1/a + 1/b + 1/c + 1/d)
...     E = (a + b) * (a + c) / (a + b + c + d)          # 기대 보고 수
...     ic = np.log2((a + 0.5) / (E + 0.5))
...     ic025 = np.log2(stats.gamma.ppf(0.025, a + 0.5, scale=1 / (E + 0.5)))
...     return np.round([a, E, ror, np.exp(np.log(ror) - 1.96 * se),
...                      np.exp(np.log(ror) + 1.96 * se), ic, ic025], 2)
>>> print(disp(60, 4940, 180, 44820))
[60.   24.    3.02  2.25  4.06  1.3   0.92]
>>> chi2, p, dof, exp = stats.chi2_contingency([[4, 296], [23, 5677]])   # Yates 보정이 기본
>>> print(round(chi2, 2))
3.62

scipy의 gamma.ppf()는 R과 달리 비율(rate) 대신 척도(scale = 1/rate)를 받습니다. chi2_contingency()도 2×2 표에서는 Yates 보정이 기본이라, 보정하지 않은 χ²는 correction=False로 구합니다.
