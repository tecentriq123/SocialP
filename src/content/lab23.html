lifelines의 와이블 모수와 이 실습의 식

같은 와이블 분포라도 프로그램마다 모수를 적는 방식이 다릅니다. 이 실습과 공통 예시는 S(t) = exp(−λ tγ)로 쓰고, lifelines는 S(t) = exp(−(t ÷ lambda_)rho_)로 씁니다. 두 식을 견주면 γ = rho_, λ = lambda_−rho_입니다(23장 d 절 '더 알아보기'의 'lifelines의 와이블 모수와 이 장의 식'). 모형에서는 위험비를 λ에 곱하므로 λ 꼴로 바꿔 둡니다.

코드 한 줄씩

  1. w.lambda_, w.rho_적합한 와이블 모형의 두 모수입니다. lifelines의 적합 결과는 이름 끝에 밑줄이 붙습니다.
  2. lam_fit = w.lambda_ ** (-w.rho_)**는 거듭제곱입니다. lambda_를 −rho_ 제곱해 이 실습의 λ로 바꿉니다.
  3. s_ours = np.exp(-lam_fit * grid ** gam_fit)바꾼 모수로 이 실습의 식을 직접 계산한 생존율 241개입니다. grid ** gam_fit은 배열의 값마다 거듭제곱을 합니다.
  4. np.abs(s_ours - S["Weibull"]).max()lifelines가 계산한 곡선과의 차이 가운데 가장 큰 값입니다. 모수를 옮겨 적을 때는 이렇게 곡선끼리 견주어 확인합니다.
  5. (np.log(2) / lam_fit) ** (1 / gam_fit)S(t) = 0.5가 되는 시점, 곧 중앙값입니다. 식과 무관한 값이어서 변환이 맞는지 확인하는 데 씁니다.
  6. ((s_ours[:30] + s_ours[1:31]) / 2).sum()0–30개월의 면적입니다. 20년 전체 면적으로 나누면 평균 생존 가운데 관찰 기간이 차지하는 몫입니다.

정리

  • 입력값은 사전 하나에 모으고 p["이름"]으로 꺼내 씁니다. 중앙값과 λ는 λ = ln 2 ÷ 중앙값γ로 바꿉니다.

assert와 np.isclose

점검에는 두 가지 도구를 씁니다. assert 조건, "메시지"는 조건이 참이면 아무 일 없이 지나가고, 거짓이면 그 자리에서 실행을 멈추고 메시지와 함께 오류(AssertionError)를 냅니다. 눈으로 출력을 확인하는 대신 코드가 스스로 확인하게 하는 문장입니다. np.isclose(a, b)는 두 값의 차이가 아주 작으면(기본 설정으로 대략 10만분의 1 이내) True입니다. 컴퓨터의 소수 계산에는 아주 작은 오차가 있어 ==로 견주면 같아야 할 값이 다르다고 나올 수 있습니다. 예를 들어 0.1 + 0.2 == 0.3은 False이고 np.isclose(0.1 + 0.2, 0.3)은 True입니다.

  3. assert (x >= 0).all(), "…"모든 칸이 0 이상인지 확인합니다.

율과 확률

분할생존모형은 진행과 사망 사이의 이동을 모형에 두지 않으므로 진행 뒤의 생존을 확인할 다른 길이 필요합니다. NICE 기술지원문서 19는 상태전이 모형을 함께 만들어 견주도록 권고합니다. 국내 지침에는 이 요구가 없습니다(23장 c 절 3단계). 여기부터 다섯 셀은 23장 b 절의 마르코프 코호트 모형을 같은 입력값으로 만들어 표 23-10을 다시 만듭니다. 비용과 QALY는 셀 19의 arm_result로 세므로, 두 모형이 다른 것은 상태 비율을 만드는 방법뿐입니다.

먼저 율과 확률을 바꾸는 함수를 만듭니다. 율은 단위 시간당 사건이 일어나는 속도이고, 확률은 정해진 기간 안에 사건이 일어나는 사람의 비율입니다. 확률은 기간에 비례하지 않으므로 나누거나 곱해 기간을 바꾸면 틀립니다. 23장 b 절 3단계의 표 23-7 세 줄을 옳은 계산과 틀린 계산으로 다시 만듭니다.

코드 한 줄씩

  1. def rate_to_prob(r, t=1):율 r이 기간 동안 일정할 때 길이 t인 기간 안에 사건이 일어날 확률 1 − exp(−r × t)를 돌려줍니다. t=1은 따로 적지 않으면 한 달이라는 기본값입니다.
  2. def prob_to_rate(prob, t=1):반대 방향의 식 −ln(1 − 확률) ÷ t입니다. 인자 이름을 p로 하지 않은 것은 입력값 사전 p와 헷갈리지 않게 하려는 것입니다.
  3. r_exit = np.log(2) / 10율이 일정하면 중앙값 = ln 2 ÷ 율이므로, 중앙 무진행생존 10개월에서 무진행 상태를 떠나는 율은 월 0.0693입니다.
  4. rate_to_prob(prob_to_rate(p_year, 12))1년 확률을 율로 바꾸면서 12로 나누고(t=12), 그 율로 한 달 확률을 구합니다. 기간을 바꾸는 일은 율에서 합니다.
  5. rate_to_prob(r_exit * p["hr_pfs"], 12)위험비는 율의 비이므로 율에 곱한 뒤 확률로 바꿉니다.

코호트 추적

모두 무진행 상태에서 출발한 코호트에 전이확률 행렬을 달마다 곱해 상태 비율의 시간표를 만듭니다. 이것이 코호트 추적(cohort trace)입니다. 모형이 내는 중앙 전체생존도 이 표에서 구해 시험의 값과 견줍니다.

코드 한 줄씩

  2. x = x @ P@는 행렬 곱입니다. 지금의 상태 비율(1행 3열)에 행렬을 곱하면 한 달 뒤의 비율이 나옵니다. 반복문이 이것을 240번 되풀이하며 rows에 쌓습니다.
  3. def median_os(P, n=1200):생존 비율(무진행 + 진행)이 0.5가 되는 시점을 구합니다. 100년(1,200개월)까지 옮겨 생존 비율이 반드시 0.5 아래로 내려가게 합니다.

  6. k - 1 + (alive[k - 1] - 0.5) / (alive[k - 1] - alive[k])두 주기 사이를 직선으로 이어 0.5가 되는 시점을 읽습니다.
