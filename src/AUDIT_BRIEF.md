## 장마다 할 일
1. **입문자로 통독**: visible을 순서대로 읽으며 실제로 막히는 곳을 적는다. 기준은 "이 독자가 여기서 읽기를 멈추거나 오해할 것인가".
   - 설명 없이 먼저 쓰인 용어(그 용어가 처음 정의되는 위치와 처음 쓰인 위치를 같이 적는다).
   - 보이는 글이 접힌 내용에 의존하는 곳.
   - 한 번에 너무 많은 개념이 나오는 곳, 같은 말의 반복, 지나치게 긴 절.
   - 논문 읽기에 꼭 필요한데 빠졌거나 접혀 있는 것 / 반대로 첫 독해에 필요 없는데 보이는 것(접을 후보).
   - 틀렸거나 오해를 부를 서술(통계·역학·경제성 평가). 의심되면 직접 계산하거나 근거를 확인한다(`source /home/claude/pylibs/env.sh`; WebSearch/WebFetch, PubMed 도구는 ToolSearch "PubMed"). 추측으로 오류라고 쓰지 않는다.
2. **학습목표와 확인 문제 분류**: '이 장을 마치면'의 각 목표와 '스스로 확인하기'의 각 문제를 세 수준으로 나눈다.
   - 독해: 논문의 질문, 분석 선택, 결과와 한계를 읽고 설명한다(의미를 이해시키는 간단한 계산 포함: 예 ICER 나눗셈, 2×2 표에서 OR).
   - 직접 분석: 자료를 구성하고 모형을 적합·진단한다, 코드를 쓴다.
   - 심화: 세부 수식, 도출, 고급 계산, 손으로 하는 긴 계산.
   장별로 개수를 세고(예: 목표 4개 중 독해 2·직접 분석 1·심화 1 / 문제 9개 중 …), 독해 수준을 넘는 목표·문제를 구체적으로 적는다(몇 절 몇 번, 무엇을 요구하는지). 접힌 내용을 읽어야만 풀 수 있는 문제도 표시한다.
3. **'처음 읽을 때' 상자 점검**: '미리 알아 둘 것'이 실제로 이 장의 첫 독해에 필요한 최소한인가(과하면 무엇을 빼도 되는가), '먼저 읽을 부분'이 현실적인 분량인가.
4. **외부 검토 의견 대조**: gpt_review.md에서 이 장과 관련된 지적을 모두 찾아 항목마다 판정한다 — **타당(고칠 것)** / **이미 반영됨** / **부분적으로 타당** / **타당하지 않음** — 과 근거(본문의 해당 문장을 짧게 인용, 위치). 판정이 '타당'이면 구체적 수정안을 한두 문장으로.
5. 프롬프트에 적힌 장별 추가 확인 사항.

## 결과물
`…/scratchpad/audit/out_<이름>.md` 한 파일(한국어, 12,000자 이내). 형식:

```
# <장 범위> 검토
## 한눈에 (5줄 이내: 이 범위에서 가장 중요한 수정 3–5가지)
## <장 번호와 제목>
### 외부 의견 대조   (표: 지적 | 판정 | 근거 | 수정안)
### 입문자가 막히는 곳   (중요한 순서로 최대 6개: 위치 | 무엇이 문제 | 수정안 | 크기: 한 문장 고치기 / 문단 고치기 / 구조 바꾸기)
### 학습목표·확인 문제   (수준별 개수 + 독해 수준을 넘는 항목 목록)
### 처음 읽을 때 상자
### 유지할 것   (2–3개)
```
칭찬을 늘어놓지 않는다. 고칠 필요가 없으면 "없음"이라고 쓴다. 확신이 없는 것은 "확인 필요"로 표시하고 이유를 쓴다. 수정안은 새 내용을 크게 늘리지 않는 방향(목표·문제에 수준 표시, 접기, 한두 문장 다리 놓기, 읽는 순서 안내, 링크)을 먼저 생각한다.
