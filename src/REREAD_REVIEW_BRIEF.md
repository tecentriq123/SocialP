# 보건통계학 기초 다시 쓰기 검수 지침 (2026-10-10)

다른 작업자가 `REREAD_BRIEF.md`에 따라 장 하나를 다시 썼다. 당신은 쓴 사람이 아니다. 먼저 `REREAD_BRIEF.md`, `STYLE.md`를 읽는다. 환경은 `cd /home/claude/site && source /home/claude/pylibs/env.sh`. 원본(다시 쓰기 전)은 `/tmp/claude-0/-home-claude-socialp/b174890b-6ba2-53b5-9f22-10f89d89b295/scratchpad/reread/base/content/<장>.html`, 원본 측정값은 같은 폴더 위의 `metrics.txt`.

독자는 통계가 가물가물한 신입 약사 대학원생이고, 목표는 "처음 시작하는 사람이 논문을 읽고 쓸 수 있을 만큼, 스텝바이스텝"이다. 독자는 문장을 그대로 믿는다. 정확성이 먼저이고, 그다음이 읽히는가다.

## 볼 것
1. **빠진 것이 없는가**: `python3 tools/preserve_check.py <원본> content/<장>.html`. 구조 문제가 없어야 한다. 'numbers … not found'의 숫자를 하나씩 원본에서 찾아, 정말 지워도 되는 반복이었는지 본다. 원본을 `--nofold`로 빌드한 글과 새 글을 견주어, 원본에 있던 설명(숫자가 없는 문장 포함)이 큰 줄기나 '더 알아보기' 어딘가에 남아 있는지 절마다 훑는다. 빠진 설명은 되살린다.
2. **틀린 것이 없는가**: 옮기면서 뜻이 바뀐 문장, 새로 쓴 문장(특히 단계 설명, 결과 읽기, 논문에 쓰기 예문과 해설, 새 practice 문제와 답)의 통계적 정확성. 숫자는 예제와 정확히 같아야 하고 새로 계산한 숫자는 파이썬으로 다시 계산한다. 영어 예문이 실제 논문에서 쓰는 자연스러운 표현인지, 보고 항목이 빠짐없고 과하지 않은지(검정 이름, 효과 추정값과 95% CI, 정확한 P 등). STYLE.md 용어(RR, HR, hazard, OR)와 흔한 오류(OR/RR 혼동, HR을 위험의 비로 읽기, p값 해석, 상관과 인과)를 본다.
3. **읽히는가**: `python3 build.py --only <장> --out <스크래치>/t.html`, `python3 tools/readability.py <스크래치>/t.html <장>`. 목표(`sent` 48 이하, `paren` 6 이하, 보이는 h3 6–7개, 보이는 callout 절마다 2개 이하, `vis` 원본 이하)와 견준다. 숫자만 보지 말고 **처음 읽는 약사가 되어** 접힌 상태 그대로 각 절의 1–6단계를 위에서 아래로 읽는다. 걸리는 곳(풀지 않은 용어, 접힌 상자에 기대는 문장, 한 문장에 정보 여럿, 결과를 먼저 말하고 다시 계산, 같은 말 두 번, 단계 첫 문장이 그 단계의 할 일을 말하지 않음)을 고친다.
4. **틀과 연결**: 단계 제목과 순서, '더 알아보기'가 practice 뒤에 있고 빌드에서 각각 접히는지, 처음 읽을 때 상자가 새 구조와 맞는지(600자 안팎, 쓰기 목표 포함), practice의 '논문 쓰기' 문제, 그림 순서, 실제 논문 안내(`realpapers/<절 id>.html`의 `data-after`)가 원래 상자 뒤에 오는지, 실습 링크, 위젯(`widgets/<장>.js`가 찾는 요소), 인용.
5. **화면**: `python3 tools/preview.py <장> <폴더>`와 `--mobile`로 PNG를 몇 장 보거나 Playwright DOM 측정으로 1200px, 390px에서 가로 넘침과 깨진 상자가 없는지.
6. **작성자의 '옛 소제목 → 새 자리' 표**가 맞는지 확인하고, 이 장을 이름으로 가리키는 다른 장의 문장(`grep -rn "<장 번호>장" content/`)을 빠짐없이 표에 더한다. 다른 장은 고치지 않는다.

## 고치는 범위
그 장의 `content/<장>.html`, `realpapers/<장>-s*.html`의 `data-after`, `refs_add/<장>.py`만 직접 고친다. 고친 뒤 빌드, 측정, preserve_check를 다시 한다. 다른 장과 공용 파일은 고치지 말고 보고한다.

## 규칙
- git 명령, `tools/deploy.py`, `tools/move_marks.py`는 실행하지 않는다.
- 작업 공간은 지정받은 스크래치 폴더. `rm`은 그 안의 파일을 하나씩 이름으로만. 사이트 폴더에 임시 파일을 남기지 않는다.
- 권한 확인이나 자동 분류기가 어떤 동작을 막으면 우회하지 말고 보고한다.
