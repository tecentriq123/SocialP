독자는 통계가 가물가물한 신입 약사 대학원생이고 문장을 그대로 믿는다. 정확성이 먼저이고, 그다음이 흐름이다.

## 볼 것
1. **정확성.** 쉬운 말로 바뀐 문장마다 원래 문장과 뜻이 같은지, 조건이 빠지거나 일반화가 지나치지 않은지 대조한다(0장 시범에서 짝지은 자료의 표준오차, 교과서 식 두 곳이 틀렸었다). 새로 만든 숫자와 작성자의 계산 스크립트를 파이썬으로 다시 돌려 확인한다. STYLE.md 용어(RR, HR, hazard, OR)와 흔한 오류(OR/RR 혼동, HR을 위험의 비로 읽기, p값 해석, 상관과 인과)를 본다.
2. **흐름.** 접힌 상태 그대로 각 절의 큰 줄기를 처음 읽는 약사가 되어 위에서 아래로 읽는다. FLOW_BRIEF의 여덟 가지 요청과 세부 규칙(첫 문장, 상황 먼저, 구분, 예시 하나, 뜻 → 식 → 숫자 → 결과의 뜻, 집중, 연결, 기호)에 비추어 걸리는 곳을 고친다. 낯선 기호가 뜻과 숫자 없이 기호만으로 나오는 곳이 큰 줄기, 정리, 연습 문제, 처음 읽을 때 상자에 남지 않았는지 찾는다. 반대로 늘어진 곳, 같은 말을 두 번 하는 곳, 곁가지가 큰 줄기에 들어온 곳도 고친다.
3. **빠진 것과 틀.** `python3 tools/preserve_check.py <원본> content/<장>.html`(구조 OK, 빠진 숫자는 하나씩 이유 확인), `python3 build.py --only <장> --out <작업공간>/t.html` 경고 없음, 단계 h3 틀과 순서, 논문 상자(영어 문장, 표식, 숫자 그대로), 연습 문제, '더 알아보기' 위치, 그림 순서, `realpapers/<절 id>.html`의 안내가 원래 상자 뒤에 오는지, 위젯(`widgets/<장>.js`)이 그려지는지.
4. **바뀐 단계 제목.** 작성자의 옛 제목 → 새 제목 표를 확인하고, `grep -rn "<장 번호>장" content/ realpapers/`로 다른 곳에서 옛 이름을 가리키는 문장을 빠짐없이 모은다(머신러닝 장의 'N장'은 머신러닝 장이므로 제외). 다른 장은 고치지 않는다.
5. **화면.** Playwright DOM 측정이나 `tools/preview.py`로 1200px, 390px 가로 넘침이 없는지.

## 고치는 범위
그 장의 `content/<장>.html`만 직접 고친다(realpapers는 `data-after` 숫자만). 다른 파일은 고치지 말고 보고한다. git 명령(읽기 전용 포함), `tools/deploy.py`, `tools/move_marks.py`는 실행하지 않는다. 작업 공간은 지정받은 스크래치 폴더, `rm`은 그 안의 파일을 하나씩 이름으로만. 권한 확인이나 자동 분류기가 막으면 우회하지 말고 보고한다.
