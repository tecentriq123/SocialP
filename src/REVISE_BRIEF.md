# 본문 수정 2–5단계 공통 지침: 독해와 직접 분석을 가르기 (2026-10-03)

사이트 원본은 /home/claude/site. 빌드: `source /home/claude/pylibs/env.sh && python3 build.py --only <ids> --out <scratch>/t.html` (`--nofold`는 접힌 것까지 펼친 빌드). 먼저 `STYLE.md`, `FOLD_BRIEF.md`(접기 방식)를 읽고, 자기 범위의 검토 보고서 `plan/audit/out_*.md`를 처음부터 끝까지 읽는다. 보고서의 장별 '입문자가 막히는 곳', '학습목표·확인 문제', '처음 읽을 때 상자' 항목이 이번 작업의 목록이다. 1단계에서 이미 고친 것(틀린 서술)은 다시 하지 않는다 — 원문을 보고 판단한다.

## 왜 하는가
독자는 통계가 가물가물한 신규 약사(사회약학 신입 대학원생)다. 논문을 읽고 쓰려고 공부하며 통계 전공자가 되려는 것이 아니다. 사이트 주인은 "양이 방대하고 아직 어렵다"고 느낀다. 검토 결과, 학습목표는 대부분 독해 수준인데 (1) '먼저 읽을 부분'이 보이는 글 전부를 가리키고 (2) 독해를 넘는 확인 문제에 표시가 없으며 (3) '미리 알아 둘 것'이 실제 필요보다 많았다. 이번 작업은 **새 내용을 쓰는 것이 아니라 처음 읽을 사람의 길을 좁히고 표시하는 것**이다.

## 주인이 정한 규칙
1. **수준 표시는 예외에만.** 표시가 없으면 독해 수준(논문의 질문, 분석 선택, 결과와 한계를 읽고 설명하기. 뜻을 이해시키는 간단한 계산 포함)이다.
   - **직접 분석**: 자료를 만들고, 모형을 적합·진단하고, 코드를 쓰는 일. 표시 `<span class="lv do">직접 분석</span>` (접히지 않는다).
   - **심화**: 세부 수식, 도출, 긴 손계산. 표시는 기존 `<span class="lv deep">심화</span>`.
2. **'처음 읽을 때' 상자** (`<div class="route">`의 `<dl>`): 다섯 줄로 맞춘다.
   - `미리 알아 둘 것`: 이 장의 첫 독해에 **실제로 쓰이는 것만**, 장이 아니라 절(가능하면 소제목)로, 링크와 함께. 본문이 그 자리에서 다시 풀어 주는 것은 뺀다. 특정 절에서만 필요한 것은 "라 절을 읽을 때 …"처럼 한정한다.
   - `먼저 읽을 부분`: 보이는 글 전부를 나열하지 않는다. **첫 독해의 최소 경로**를 절별로 적는다(어느 절의 어느 소제목까지). 사이트의 첫 독해 경로는 0장 → 1장 가·나·다·사 → 2장 가 → 3장 가 → 5장 가 → 6장 가·다·라 → 7장 가·나 → 분석 고르기 연습 → 8장(다·라·마는 핵심만) → 9장이고, 그 밖의 절과 장은 "논문에서 이 방법을 만났을 때" 읽는다. 상자는 이 구분을 그 장에 맞게 적는다(경로에 든 절 / 만났을 때 읽는 절).
   - `나중에 읽을 부분`: "접힌 '심화' 부분은 모두 나중에 읽습니다." 한 문장 + 꼭 짚어 둘 것 한두 개. 접힌 것의 목록을 늘어놓지 않는다.
   - `이 장을 마치면`: **독해 목표만**, ①②③… 번호, 예제 숫자가 아니라 일반 문장으로(예시는 괄호 안에). 독해와 분석이 한 문장에 섞인 목표는 나눠 쓴다. 풀이 없는 용어를 쓰지 않는다.
   - `직접 분석할 때` (새 줄, `<dt>직접 분석할 때</dt><dd>…</dd>`): 독해를 넘는 목표를 여기로 옮기고, 그때 읽을 곳을 적는다 — 각 절의 '내 연구에 쓸 때', 파이썬 출력·코드 상자, 접힌 계산 과정, 짝이 되는 실습(`<a href="#labNN">실습 N</a>`). 해당 사항이 없는 장은 이 줄을 만들지 않는다.
   - 상자 전체가 지금보다 짧아져야 한다(목표: 600자 안팎, 길어도 800자).
3. **확인 문제** (`<div class="practice">`): 유형 꼬리표(`<span class="qt">계산</span>` 등)는 그대로 둔다. 독해 수준을 넘는 문제에만 유형 꼬리표 바로 뒤에 수준 표시를 붙이고(`<span class="qt">계산</span><span class="lv deep">심화</span>…`), **그 묶음의 맨 뒤로 옮긴다**(`<li>` 통째로, 답 포함). 접힌 상자의 식이 있어야 풀리는 문제는 (가) 필요한 식이나 중간값을 문제 안에 주어 독해 수준으로 만들거나 (나) 표시를 붙이고 "접힌 '…' 상자의 식을 씁니다"라고 적는다 — 뜻을 이해시키는 계산이면 (가), 손계산 연습이면 (나). 문제를 지우지 않는다. 답과 풀이의 숫자는 바꾸지 않는다(문제를 고쳐 숫자가 달라지면 직접 계산해 확인한다). 묶음에 독해 문제가 하나도 남지 않으면 보고한다.
4. **'내 연구에 쓸 때'**: 1–4장에서는 모두 접는다(이미 그렇게 맞춰 두었다). 5장부터는 보이는 것은 보이게 두고 접힌 것은 접힌 채로 둔다(새로 접지도 펼치지도 않는다). 상자 안의 파이썬 함수 이름 줄도 그대로 둔다. '처음 읽을 때' 상자에서 '직접 분석할 때 읽는 부분'으로 분류할 뿐이다.
5. **접기**: 검토 보고서가 '접을 후보'로 든 것 가운데 첫 독해에 필요 없는 것을 접는다(지우지 않는다). 방법은 FOLD_BRIEF.md 그대로: 소제목에 심화 꼬리표, `<!--FOLD:제목-->…<!--/FOLD-->`, 필요하면 한두 문장 요약을 보이게 남기고 나머지를 접음("자세히 보기: …"). **교재 목차의 절은 없애거나 순서를 바꾸지 않는다.** 접은 뒤 보이는 글이 접힌 내용에 기대면 안 된다(그 경우 한 구절 풀이를 본문에 넣는다). '정리'가 접힌 심화의 요약으로 채워져 있으면 독해 내용으로 바꾸고 심화 항목은 한 줄로 묶는다.
6. **풀어 쓰기**: 보고서가 짚은 "정의 전에 쓰인 용어", "접힌 내용에 기대는 문장"은 한 구절 풀이나 링크로 고친다. 새 문단을 쓰지 않는다.
7. 하지 않는 것: 통계 내용·숫자·그림 바꾸기(오류를 찾으면 고치지 말고 보고), 새 절·새 예제 쓰기, 논문 상자의 표식(`<span class="mk">`) 위치 바꾸기, `tools/move_marks.py` 실행, build.py·shell.html·다른 범위의 장 수정.

## 문체
합니다체. 담백하게. 쌍점(:)·줄표·세미콜론을 새 문장에 쓰지 않는다(상자의 dt/dd 구조는 그대로). 통계 용어는 처음 나올 때 한글(영어) 병기, STYLE.md 용어(상대위험도 = RR, 위험비 = HR, 위험률 = hazard, 오즈비 = OR)를 따른다. 약학·의학 용어는 풀지 않는다.
