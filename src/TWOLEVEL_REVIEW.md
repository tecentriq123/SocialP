# 본문과 심화 나누기 검수 지침 (2026-10-12)

당신은 작성 과정을 보지 않은 **독립 검수자**다. 고친 장을 원본과 대조해 **뜻이 바뀌거나 조건이 빠진 문장, 틀린 숫자, 끊긴 연결, 깨진 참조, 지침 위반**을 찾아 고친다. 작성 지침은 `TWOLEVEL_BRIEF.md`(특히 1, 2, 3, 9, 9-1)와 `TWOLEVEL_EXPAND.md`(유명한 실수의 집 표), 문장 규칙은 `FLOW_BRIEF.md`.

## 볼 것 (중요한 순서)
1. **뜻과 조건.** 줄이거나 옮기거나 새로 쓴 문장마다 원본의 해당 문장과 대조한다. 줄이면서 조건(언제만 맞는지)이 빠졌는지, 쉬운 말로 바꾸며 뜻이 미끄러졌는지(지난 검수에서 직선 가정이 깨질 때의 방향, 연관과 효과, 그림 캡션의 설명이 틀린 적이 있다).
2. **옮긴 내용.** 본문에서 접힘('더 알아보기' 상자, 단계 안의 `<!--FOLD:…-->`)으로 옮긴 내용이 그 자리에 실제로 있고 앞뒤와 이어지는지, 옮기며 숫자가 사라지거나 바뀌지 않았는지, 상자 안에서 같은 말이 두 번 나오지 않는지. 본문이 상자 이름으로 가리키는 곳마다 그 이름의 상자가 실제로 있는지.
3. **지운 것.** 작성자의 지운 것 목록마다 "같은 내용이 남아 있는 곳"이 정말 있는지, 지운 것 가운데 세 질문(누구·무슨 질문, 결과값 해석, 결론을 바꿀 조건)에 필요한 것이 없었는지. 목록이 틀렸으면 목록 파일을 고친다.
4. **숫자.** 새로 쓰거나 옮긴 곳의 숫자를 원본과 `gen/nums_<장>.py`로 대조하고, 새 연습문제의 숫자는 다시 계산한다(작성자 스크립트가 있으면 실행).
5. **새 내용.** 새로 넣은 사실(임상 기준, 보고 지침의 성격 등)이 맞는지. 확인할 수 없으면 보고한다.
6. **지침.** 처음 읽을 때 상자가 보이는 세 줄 + 접힘인지, '이 장의 핵심'에 분석 약어가 없는지, 유명한 실수가 집이 아닌 곳에서 되풀이되지 않는지(집에서는 한 곳에만), 절마다 연습문제가 네 개 이하이고 장 전체에 세 역할(새 결과 해석, 잘못된 해석 찾기, 내 연구에 쓰기)이 있는지, 캡션이 '어디를 볼지'인지.
7. **문장.** 새 문장에 쌍점·줄표·세미콜론이 없는지, 낯선 기호를 뜻 없이 쓴 곳, 연결이 끊긴 곳.
8. **빌드.** `source /home/claude/pylibs/env.sh; cd /home/claude/site; python3 build.py --only <장> --out <작업공간>/t.html` 경고 없음, `python3 tools/preserve_check.py <원본> content/<장>.html`.

## 고치는 방법
- 확실한 오류는 맡은 장의 `content/<장>.html`(캡션이면 `gen/fig_<장>.py`를 고친 뒤 실행)과 작성자의 지운 것 목록 파일에서 직접 고친다. 고친 곳마다 원문 → 새 문장 → 이유를 보고한다.
- 판단 문제(더 접을지, 더 남길지)는 고치지 말고 제안으로.
- 예제 숫자와 `paper` 상자의 영어 문장·숫자는 바꾸지 않는다. 다른 장·실습·realpapers는 고치지 않는다(보고만). 같은 시간에 다른 검수자들이 다른 장을 보고 있다.
- git 명령(읽기 전용 포함), `tools/deploy.py`, `tools/move_marks.py` 실행 금지. `rm`은 작업 공간 안의 파일을 하나씩 이름으로만. 사이트 폴더에 임시 파일을 남기지 않는다(Playwright 스크린숏도 작업 공간 절대 경로). 권한 확인이나 분류기가 막으면 우회하지 말고 보고한다.
