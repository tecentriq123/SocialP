# 설명 방식 전환 검수 지침 (2026-10-14)

당신은 작성 과정을 보지 않은 **독립 검수자**다. 맡은 장이 `EXPLAIN_BRIEF.md`(설명 방식 지침)에 따라 서술 중심에서 '핵심 한 줄 → 질문 단위 → 비교표 → 즉 → 미리 보기 한 줄' 모양으로 바뀌었다. 고치기 전 판(작성자 작업 공간의 `base/`)과 대조해 **뜻이 바뀌거나 조건이 빠진 문장, 틀린 숫자, 끊긴 연결, 깨진 참조, 지침 위반**을 찾아 고친다. 검수 방식의 기본은 `TWOLEVEL_REVIEW.md`와 같다.

## 볼 것 (중요한 순서)
1. **뜻과 조건.** 서술을 표 칸·목록·질문형 소제목으로 줄이면서 조건(언제만 맞는지)이 빠지거나 뜻이 미끄러진 곳. 새 **비교표의 칸마다** 통계적으로 맞는지 확인한다(장점·단점·언제 쓰나 칸에서 지나친 일반화가 잘 생긴다). 지난 검수에서 걸린 예: 관례인 기준을 사실처럼 쓰기, 편향의 방향 혼동, '드문/흔한' 같은 말의 장 안 불일치, 무작위배정 비율 조건 누락, 짝을 무시한 신뢰구간의 방향, 충돌변수를 '치료 뒤 변수'로만 일반화.
2. **숫자.** 표로 옮기거나 새로 쓴 숫자를 원본과 `gen/nums_<장>.py`(있으면)로 대조하고, 새 숫자는 다시 계산한다(작성자 스크립트가 있으면 실행). 논문 상자의 영어 문장과 숫자는 바뀌면 안 된다(표식 정리와 '고칠 곳을 찾아보는 문단' 제목 표시는 예외). 같은 영어 문장이 5단계와 6단계에 두 번 나오지 않는지.
3. **옮긴 것과 지운 것.** 접힘으로 옮긴 내용이 그 자리에 있고 앞뒤가 이어지는지, 본문이 이름으로 가리키는 상자·단계·h4가 실제로 있는지, 작성자의 지운 것 목록마다 '같은 내용이 남아 있는 곳'이 정말 있는지. 세 질문(누구·무슨 질문, 결과값 해석, 결론을 바꿀 조건)에 필요한 것이 접히거나 지워지지 않았는지. **원리 설명(왜 그런지)이 사라지지 않았는지**(이번 전환에서 가장 조심할 것).
4. **주인의 기준.** 처음 읽는 약사가 되어 접힌 상태로 끝까지 읽고 판단한다: 난이도, 구성(뒤에서 배울 것이 먼저 나오지 않는지), 가독성(풀이 전 약어, 약어만 반복, 한 문장에 조건 셋 이상, 비문), 설명 방식(쉬운 말 → 쓰임새 → 장단점 → 맛보기). '즉'이 단계마다 하나 이하인지, 미리 보기가 절 끝 한 줄(`<b>다음 절 미리 보기.</b>`)인지, '이 장의 흐름' 표에 숫자나 미학습 약어가 없는지.
5. **틀과 연결.** 장·절 제목과 id, 단계 이름과 번호(PART 1·2는 여섯 단계), 그림 표식과 순서, 위젯(빌드한 페이지에서 그려지고 오류가 없는지), 인용, 실습 링크, `realpapers/`가 원래 상자 뒤에 오는지, 유명한 실수가 집 한 곳에만(TWOLEVEL 9-1), 스스로 확인하기 절마다 네 문제 이하와 세 역할. 다른 파일(`grep -rn "<장 번호>장" content/ realpapers/ gen/`)이 이 장의 h4·상자 제목을 이름으로 가리키는데 그 제목이 바뀌었으면 보고.
6. **휴대폰.** Playwright 390px에서 페이지 가로 넘침이 없고, 새 표의 안쪽 가로 스크롤이 없는지(논문 상자 속 원래 표는 예외). 스크린숏 몇 장을 Read로 직접 본다.
7. **문장 규칙.** 새 한국어 문장과 표 칸에 쌍점·줄표·세미콜론이 없는지('(예: …)'는 기존 관례로 허용, 영어 예문의 학술지식 세미콜론 허용).
8. **빌드.** `source /home/claude/pylibs/env.sh; cd /home/claude/site; python3 build.py --only <장> --out <작업공간>/t.html` 경고 없음, `python3 tools/preserve_check.py <base 판> content/<장>.html` 결과 해석.

## 고치는 방법
- 확실한 오류는 맡은 장의 `content/<장>.html`(캡션이면 `gen/fig_<장>.py`를 고친 뒤 실행)과 작성자의 지운 것 목록 파일에서 직접 고친다. 고친 곳마다 원문 → 새 문장 → 이유를 보고한다.
- 판단 문제는 고치지 말고 제안으로.
- 다른 장·실습·realpapers는 고치지 않는다(보고만). 같은 시간에 다른 검수자와 작성자가 다른 장을 보고 있다.
- git 명령(읽기 전용 포함), `tools/deploy.py`, `tools/move_marks.py` 실행 금지. `rm`은 작업 공간 안의 파일을 하나씩 이름으로만. 사이트 폴더에 임시 파일을 남기지 않는다(스크린숏도 작업 공간 절대 경로). 권한 확인이나 분류기가 막으면 우회하지 말고 보고한다.
